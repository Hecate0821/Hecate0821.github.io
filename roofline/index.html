FSDP：切的是参数、梯度和优化器状态

FSDP（ZeRO-3）把每层的参数平均切成 F 份，每张卡常驻 1/F。前向到这一层之前先 all-gather 出完整的 BF16 权重，用完就扔（reshard_after_forward）；反向再 all-gather 一次，算出完整梯度后 reduce-scatter，每张卡只留自己那份梯度，再在本地对自己那份做 Adam。通信量和 token 数无关，只和参数量有关；能不能藏住，取决于这一层的计算够不够长。

  • dense FSDP 和 CP 共用一个分片维度。torchtitan 把 dense 参数切在 dp_shard × cp 上，所以开 CP 不减少分片数。
  • expert FSDP 是单独的一维。EP 从 dp_shard × cp × tp 里借走 E，剩下的是 expert 的 FSDP 度（edp_shard）。EP 越大，expert 每张卡持有的越多、需要 gather 的越少；EP 用满时 expert FSDP 消失。
  • HSDP。R > 1 时副本之间每步做一次梯度 all-reduce（2(R−1)/R × 本卡分片字节），把 all-gather 限制在 1/R 的卡内。分片组放进一个 NVLink 域，跨机就只剩每步一次的 all-reduce。左侧“更多”里的“HSDP 副本数”改的就是它。
  • reshard_after_forward。关掉它，前向 gather 的权重留到反向，省掉一次 all-gather（字节从 3 份变 2 份），代价是整个模型的 BF16 权重常驻。
  • Megatron 没有这一维。它的分布式优化器只切 optimizer 状态，梯度 reduce-scatter 和参数 all-gather 每个 step 只做一次，见一个 step。

CP：切的是一篇文档的 token

CP 把一篇长文档切成 C 段，每张卡只持有 S/C 个 token。线性层、MoE、norm 都只看自己的 token，不需要通信；只有 attention 要看到前面所有 token 的 K / V。Ring、AllGather、Ulysses 是拿到远端 K / V 的三种办法，它们在字节、调用次数、负载均衡和对头数的要求上各不相同。左侧的“全注意力 CP”切的就是这三种（Megatron 里叫 p2p、allgather、a2a）。

Ring

K / V 块沿环转 C−1 次，每一步算本地 Q 对当前 K / V 块的局部 attention，用 log-sum-exp 合并。通信和计算交替，可以重叠，但要走 C−1 步依赖链；反向 dK / dV 也要绕环回来（FP32 累加）。causal 下连续切分，最后一段要算最多的块；把序列切成 2C 段首尾配对（head-tail / zigzag）来平衡。

ring-flash-attention · Megatron p2p CP · PyTorch CP（ring 旋转）

AllGather（SPAG）

每层先 all-gather 全部 K / V，本地 Q 对完整前缀做一次 attention；反向把 dK / dV reduce-scatter 回去。按 KV 头分块可以流水、也能控制临时显存。字节和 Ring 一个量级，但只有一个调用，GQA 的 KV 头少时很划算。Llama 3 训练用的就是这一种。

torchtitan KV all-gather CP · Megatron --allgather-cp

Ulysses

两次 all-to-all 把“按 token 切”换成“按头切”：每张卡拿 H/C 个头的完整序列做普通 attention，再换回来。causal 负载天然均衡，调用固定 8 次（F+B）。代价是 Q / O 也要上网，KV 头数小于 C 时要复制 KV（K′ = max(Hkv, C)），而且每个 TP rank 的头数必须被 C 整除。

混合架构里的 CP

  • 线性注意力层（GDN / KDA）不需要 K / V。按段传状态时，每张卡先按零初始状态扫自己那段，再交换每段的末状态（Hv × dk × dv，FP32），本地做一次前缀修正，字节和序列长度无关；GDN 在 Megatron 里只能按头 a2a。左侧的“线性注意力 CP”选的就是这两种。所以 Qwen3.5 / Qwen3.8 / GLM / Kimi 这种 3:1 混合模型，CP 的大头只来自那 1/4 的 full-attention 层。
  • 滑窗层（Muse Spark 的 46 层）只要邻居的最后 W 个 token。Ring / AllGather 退化成一次 halo 交换，字节 ≈ W × KV 宽度，和 C 无关；Ulysses 仍然要两次全量 all-to-all，所以滑窗层越多，Ulysses 越吃亏。
  • MLA 只有一份 latent KV。AllGather 的字节最省（每 token 512 + 64 维）；Ulysses 下 latent 不能按头切，每张卡都要拿完整的 latent，KV 部分退化成 all-gather，Q / O 仍走 all-to-all。
  • DSA（GLM）的 indexer 也要全量 key。每个 query 只看 top-2048 个 token，attention 核心的 FLOP 随 S 线性增长，但 indexer 的打分仍然是 S² 量级；CP 要把 indexer 的 key 一起 gather。

EP：切的是 expert，换来的是 token 搬运

每张卡持有 Z/E 个 expert，token 按 router 的选择去找 expert。attention 一侧的 token 按 DP / CP 切在各卡上，而一个 token 的 k 个 expert 大概率在别的卡上。五个后端的区别在四件事：线上搬几份（按 expert 槽位、按目的 rank 去重、还是整份广播）、谁发起（host 调 NCCL，还是 kernel 自己读写对端显存）、CPU 要不要知道大小（每层一次 D2H 同步，还是全程留在 GPU 上），以及通信能不能和 GEMM 叠在一起。左侧的“EP 通信”（torchtitan）切的就是这五个；Megatron 的 alltoall / DeepEP / HybridEP 按各自的字节算，不在这里比。

训练：三遍 GEMM，各收缩哪一维

前向 Y = X·Wᵀ 收缩 K，dgrad dX = dY·W 收缩 N，wgrad dW = dYᵀ·X 收缩 M（token）。低精度的块必须沿收缩维排，所以同一个张量在不同的 GEMM 里要不同方向的块。只看 GEMM 算力，反向两遍、前向一遍：时间 ≈ (1/rf + 2/rb) / 3，FP8 全程 0.5，只有前向 FP8 是 0.83，FP4 全程 0.25，只有前向 FP4 是 0.75。下表再加上量化 kernel、转置副本和 per-token scale 的实际开销。反向用什么精度、梯度对应哪个函数，放在 RL · QAT 与反向精度。

1D 和 2D：转置之后 scale 还能不能用

1×B 的块只沿一个方向连续：沿 K 排的 scale 拿去做收缩 N 的 dgrad，等于 scale 沿收缩维在变，又不是按收缩维分的块，块缩放 MMA 用不了，只能从 BF16 再量化一份另一个方向的。B×B 的方块转置后还是方块，scale 对两个收缩方向都是块常数，一份 qdata 就够，只需要两种 scale 摆放（swizzle）。代价是方块里 B 行共用一个 scale，outlier 影响更多元素，所以方块只用在权重上，激活和梯度一般不用：TE 也不支持两个操作数都是 2D。

推理的并行和训练不是一回事

同样叫 TP、EP、DP，推理和训练切的东西、换来的东西都不一样：推理一步只有一个前向，行数是“并发 × 投机宽度”，要的是单用户速度、KV 容量和单卡吞吐；训练每个 micro-batch 有几千到几万行、要反向和优化器，要的是放得下激活和参数、通信藏得住。训练那一侧见后训练 · 并行。

    四种 draft 方法

    验证都一样：目标模型对 k 个 draft token 再加一个 bonus 位置做一次宽度 k+1 的 forward，按拒绝采样逐个接受，输出分布和不开投机完全相同。区别在 draft 从哪来、每步读多少权重、k 个 token 是一个一个出还是一次出。

    方法draft 从哪来出 k 个 token本页怎么算 draft常见 k / 接受长度

    接受率 α 和 draft 长度 k

    每个位置以概率 α 被接受、第一次拒绝就停（i.i.d. 近似）时，一步平均产出 τ = (1 − αk+1) / (1 − α) 个 token（含 bonus）。左侧“每步平均多接受的 token”就是 τ − 1，这一页由它和 k 反解出 α。α 越高，长 draft 越值；α 低时 k 再大也只是白白加宽验证。块式 draft（DFlash / DSpark）的 α 不是常数，越往后越低，这里只看量级。

    放到 RL rollout 里

    训推不一致：rollout 和训练算的不是同一个函数

    RL 用推理引擎采样，用训练框架算梯度。两边的 kernel、并行方式、精度和 batch 组成都不同，同一个 token 的 log-prob 在两边对不上：πrollout ≠ πtrain。算法上是 on-policy，实际优化的却是 off-policy 目标。MoE 会把差异放大：router logit 的一点差别就能换掉 top-k 里的一个 expert，整层输出跟着跳；差异随训练积累，严重时 reward 崩掉。

    来源为什么两边不一样怎么修
    kernel 与归约顺序attention、GEMM、all-reduce 的分块和累加顺序不同，浮点结果不同；推理的结果还随 batch 组成变（continuous batching 把别的请求拼进同一个 GEMM）batch-invariant / 确定性 kernel；训练前向直接调用推理 kernel（true on-policy）
    MoE 路由router 的微小差异换掉 top-k 里的 expertR3（rollout routing replay）：推理返回每个 token 选中的 expert，训练按它路由
    量化rollout 用 FP8 / FP4，训练用 BF16；前向的量化误差是主因训练前向复现同样的量化、逐位对齐量化结果；QAT；或两边统一精度
    采样top-p / top-k 截断了推理侧的分布，训练侧按完整 softmax 算 log-prob返回采样掩码，训练侧回放同样的支撑集
    tokenization多轮 agent 里重新分词、chat template 裁掉历史 reasoning、tool call 重渲染，训练看到的 token 和 rollout 不同TITO（token in, token out）：直接把 rollout 的 token id 交给训练
    权重版本异步 RL 里 rollout 用的是旧权重记录每个 token 实际服务的权重版本；decoupled PPO 和重要性采样修正

    两类办法：算法上修正，工程上对齐

    算法上修正。把 πtrain / πrollout 当重要性权重乘进策略梯度。TIS 把权重截断在上限 C（token 级或序列级），MIS 直接把比值越界的 token 或序列 mask 掉，IcePop、KPop 是同一思路的变体。它们不消除差异，只让梯度不被少数离谱的 token 带偏，代价是有效样本变少。

    工程上对齐。让两边算的尽量是同一个函数：R3 消掉路由差异，量化逐位对齐消掉精度差异，TITO 消掉 token 差异，batch-invariant kernel 加上训练前向复用推理 kernel 消掉剩下的数值差异，log-prob 差可以做到 0。代价是 rollout 变慢、训练要跟推理用同样的 kernel。实际做法是两者都用：先对齐到差异很小，再用 IS 兜底。

    开源实现怎么做权重同步

    QAT：训练时就让模型见过量化

    低精度 rollout 的权重是从 BF16 主权重量化出来的。训练完再量化（PTQ）在 RL 里有两个问题：rollout 的策略和训练的策略差一个量化误差，而且这个误差每一步都在变；FP4 / INT4 这种窄格式下，差异大到重要性采样兜不住。QAT 在训练前向里先把权重（和激活）按 rollout 的格式量化、再反量化（fake quant），反向用直通估计（STE）把梯度原样传给 BF16 主权重，训练优化的就是 rollout 实际执行的那个量化函数。

    • 显式 fake quant。前向 W → Q(W) → 反量化 → BF16 GEMM，rollout 用同一种量化（slime / Miles 的 INT4 QAT 配 W4A16 rollout）。GEMM 算力和 BF16 训练一样，只多一个量化 kernel；Hopper 没有 INT4 tensor core，W4A16 rollout 省的是显存和带宽，算力仍是 BF16。
    • 隐式 QAT。前向直接跑真 FP4 GEMM，反向把前向那份量化值反量化回 BF16 再做 dgrad / wgrad（TE 的 dequantized 反向）：梯度对应实际执行的量化函数，和 fake quant + STE 等价，前向还更快。

    反向用什么精度

    训推 log-prob 的差异只取决于前向；反向精度决定的是梯度对应哪个函数。BF16 反向用原始值（high_precision）时，求的是没量化的 y = x·w，和前向对不上，4-bitter Lesson 观察到偶发的梯度尖峰；用前向那份量化值反量化回 BF16（dequantized）时，梯度对应实际执行的量化函数，等价于 fake quant + STE，也就是 QAT 的梯度，只是前向换成了真 FP4 GEMM；全程低精度反向再多一份梯度噪声。三种反向的 loss 和传回的 dY 都来自同一个量化前向，所以训推一致性相同，差别只在梯度。两篇最新报告在这里分歧：4-bitter Lesson 要求梯度对应实际执行的函数，选 dequantized；miniTE 拿高精度参考梯度检验反向，选原始值，它的 learner 加速也是在这个口径下测的。截至 2026-10-29，Miles 脚本默认仍是原始值，dequantized 是进阶选项；两种反向还没在同一设置下比过学习质量。

    格式与 scale

    E2M1 只有 ±{0, 0.5, 1, 1.5, 2, 3, 4, 6} 这 15 个值，动态范围约 3.6 个二进制档，所以 FP4 必须配小块；E4M3 有约 17.8 档，块可以大一些。scale 的格式决定块 amax 能不能精确对齐到元素的最大码字：E8M0 只能是 2 的幂，要向上取整，平均浪费约半档；E4M3 有尾数能对齐到 6，但范围只到 448，所以 NVFP4 要再加一级 FP32。两级分工不同：16 个一组的 E4M3 块 scale 沿 K（hidden）切，管 hidden 方向的大小差异；FP32 那一级只给块 scale 定量程，取 amax 的范围才是“按张量”和“按 token”的区别。按张量时，一个 token 的量化结果要看同一个张量里的其他行：推理侧 continuous batching 把别的请求拼进同一个 GEMM，训练侧把整条序列一起算，后面 token 的 amax 会改写前面 token 的块 scale 取整。按 token 只看自己这一行，与 batch 组成、prefill / decode、训练 / rollout 都无关，而且只沿 M 变，仍能在 epilogue 里乘。

    Y[m,n] = Σ_k X[m,k] · W[n,k]
scale 只沿 M 或 N 变：Y = diag(s_x) · (X'W'ᵀ) · diag(s_w)        → 提到 epilogue 里乘一次（按张量 / 通道 / token）
scale 沿 K 变：      Y = Σ_kb s_x[m,kb] · s_w[n,kb] · (X'W'ᵀ)_kb → 每个 K 块都要乘，只能在 MMA 里做（blockwise）

    Hopper 的 tensor core 不能在 K 方向乘 scale，DeepGEMM 每 128 个 K 把部分和取到 CUDA core 上乘 scale 再累加，所以 block FP8 的块是 128。Blackwell 的块缩放 MMA 在硬件里乘 scale，块才能缩到 32 或 16，但 scale 必须是 2 的幂（E8M0）或 E4M3：block FP8 的 FP32 scale 在 Blackwell 上要先取整成 UE8M0，SGLang 和 vLLM 在加载时 requant，这份契约的边界上出过好几个 bug（见数据与发布 · 量化）。

    参数量都由下面的结构字段现场算出来，和官方数字对照。三个比例决定了推理和训练卡在哪里：每 token 激活的参数占总参数多少（MoE 稀疏度），全注意力层占多少（KV 随上下文增长的部分），expert 有多“细”（moe_intermediate 越小，每读一个字节能做的 FLOP 越少）。

    每条序列的缓存随上下文怎么涨

    按 BF16 KV、FP32 线性注意力状态、单卡不切分来算。全注意力层的 KV 随 n 线性增长；线性注意力层的递推状态是常数，和 n 无关。所以混合架构的曲线前面平（状态占大头），过了交点 n* = 状态 ÷ 每 token KV 才开始涨。双对数坐标下，平段是水平线，涨段是斜率 1 的直线。灰色虚线是当前模型的两个分量。

    同一个结构，在推理和训练里是两回事

    结构推理里是什么训练里是什么
    GQAdecode 读整段 paged KV，算术强度约 2·Hq/(Hkv·字节)；TP 超过 Hkv 后 KV 头只能复制varlen / TE fused attention，反向 ≈ 2.5× 前向；CP 要么 KV 绕环（p2p），要么 all-gather，要么 Ulysses 按头 a2a
    MLAdecode 用 absorb：q 先乘 Wuk 到 latent，在 576 维 latent 上做 MQA。latent 没有头维度，TP 切不开，每卡复制，只能靠 DCP 切Megatron 不 absorb：kv_b 把 K/V 展开成每头再做 MHA；q/kv 下投影在 SP 下各 rank 只算本地 token
    DSAindexer 每步扫 n/4 个池化 key，主注意力只读 top-2048 个 latent；n ≤ 2048 时 indexer 整个跳过indexer 在每个 TP rank 上对整组序列重复算，还多一个 indexer KL loss；CP 只能 all-gather latent K

    输出头每个请求只算最后一个 token 的 logits，再采样整段序列都算 logits + CE，词表 15~25 万时是最大的单个算子

    为什么要拆成两张算子图

    同一个模型，推理和训练发出的 kernel 几乎没有重合。推理一步只有一个前向，而且大部分 decode kernel 的行数是“并发请求数 × 投机宽度”，几十到几百行，权重和 KV / 状态的读取占主导；kernel 的选择（paged attention、absorbed MLA、递推状态更新、在 graph 里的 lm_head、采样）和 CUDA graph 的补齐阶梯决定了时间。训练一个 micro-batch 有几千到几万行，每个算子都要前向、dgrad、wgrad，外加重算、整段 CE、梯度同步和优化器，kernel 是 FLA chunk、TE / cuDNN attention、grouped GEMM，瓶颈多半在算力和通信。把两边塞进同一张算子表，只能得到两边都不对的数。

    推理核心的口径

    • 行数。decode 的行数 = 请求数 × (1+k)。CUDA graph 下按引擎的阶梯补齐：SGLang 和 TokenSpeed 按请求数补齐，vLLM 按 token 数补齐。权重 GEMM、norm、lm_head（在 graph 里时）按补齐后的行算；读 KV、读写状态的 kernel 只按真实请求算（表里标“按真实行”）。
    • 层边界。每层两次 TP all-reduce。SGLang 对 Qwen / Kimi 在 T ≤ 2048、没开 DP-attention 时融合 AR + 残差 + RMSNorm；vLLM 只对 Qwen 在 torch.compile 下、消息小于阈值时融合；TokenSpeed 除 GLM 外都融合。没融合时 norm 单独一个 kernel。
    • GQA。QKV GEMM → QK-norm + RoPE + KV 写入 → paged decode（读 B·n·2·Hkv·dh 字节）→ 输出门 → o_proj。
    • MLA / DSA。fused_qkv_a 各卡复制 → norm → q_b → （DSA：indexer 投影 + n/4 个池打分 + top-k）→ Wuk absorb → latent MQA（DSA 只读 ≤ 2048+3 个 latent）→ Wuv → o_proj。latent KV 每卡复制，DCP 才能切。prefill 走 MHA，SGLang / TokenSpeed 每个 chunk 重新展开前缀。
    • 线性注意力。in_proj → 短卷积状态更新 → 递推状态更新（读写 Sl = Hv/tp·dk·dv·字节）→ gated norm → out_proj。状态流量倍数：普通 decode 2·Sl（TokenSpeed KDA 3·Sl）；投机验证 SGLang (N+3)·Sl、vLLM (N+1)·Sl、TokenSpeed ≈ 3·Sl。prefill chunk kernel 在 SGLang SM100 和 vLLM GDN 上会把 h 写回 HBM。
    • MoE。router 各卡复制 → （Kimi K3：latent 下投影）→ routed expert（碰到的 expert 数 = E·(1−(1−k/E)T)，每个碰到的 expert 读一遍权重）→ shared expert（在 graph 下另一个 stream，藏在 routed 后面）→ （K3：latent 宽度 AR + 上投影）。默认并行方式：SGLang 沿 F 按 TP 切；vLLM 开 EP 后是 all-gather + reduce-scatter；TokenSpeed 是 replicated-input EP，每卡对全部 token 做 router，结果 all-reduce。DeepEP 在三家都是选项。
    • 每步一次。lm_head（SGLang、TokenSpeed 在 graph 里，按补齐行）→ logits all-gather → 采样（TokenSpeed 在 graph 里）。eager 时每个 kernel 一次 CPU launch；graph 时一次 replay。vLLM 开 DP 时每步一次 CPU 侧同步。
    • 投机解码。验证一步（宽度 k+1）+ draft + 提交（线性注意力要把接受位置的状态写回）。draft 按方法分开算：MTP 按目标模型一层的平均代价，第一步按验证宽度、之后每步 1 行，再加 k 次 lm_head；EAGLE-3 一次 3D → D 投影 + 每步一层 dense + 32K 裁剪词表；DFlash 用目标特征投影出 5 层的上下文 K / V，再对 B·(k+1) 行做一次 5 层 forward + 全词表 lm_head；DSpark 同 DFlash（B·k 行），外加 k 次 [B, 256] × [256, V] 的 Markov 偏置。draft 层按 dense（≈ 12·D² 参数）、8 个 KV 头 × 128 算，外挂 drafter 的权重和上下文 KV 计入显存。TPOT = 一步总时间 ÷ (1 + 平均多接受的 token)。
    • 显存。权重按部分切：注意力和线性层按 attention TP 切，expert 按 N 切，router / latent 投影 / MLA 的 a 投影复制；KV 池 = mem_fraction × 显存 − 权重 − 预留；线性状态按每请求槽数（SGLang 1 + prefix 1 + 投机 4；TokenSpeed 2；vLLM 1 + k）。

    训练核心的口径

    • 三遍。每个 GEMM 的 fwd / dgrad / wgrad FLOPs 相同；wgrad 的字节多一份 FP32 main_grad 读写；FP8 时每个 GEMM 输入多一次量化。非 GEMM 的反向全记在 dgrad，按前向的 2 倍或 3 倍算。
    • 注意力核心。反向 2.5× 前向。GQA 每 token 平均看 S/2 个 key；MLA 训练不 absorb，按 (dqk+dv)/2 每头算；DSA 训练是 absorbed 稀疏 MLA，indexer 在每个 TP rank 上重复算，再加 KL loss。
    • FLA chunk（C=64），每个 value head 每 token。GDN 前向 6KV + 7.25CK + 4CV + 0.5C²，反向 16KV + 18CK + 10CV + 4C²；KDA 前向 6KV + 3.5CK + 4CV + 0.5C²，反向 16KV + 9CK + 10CV + 4C²。h 不保存，反向重算。
    • MoE。R = 本 rank token × k × 不均系数。permute / unpermute 是纯搬运；grouped GEMM fc1 / fc2。EP a2a 每层 dispatch + combine 前向各一次、反向各一次，共 4 次；full 重算或重算 moe 模块时再 2 次（torchtitan 默认重算不重放 a2a）。alltoall dispatcher 每个 token 发 k 份，DeepEP / HybridEP / Dist-MoE 按 rank 去重，发 ep·(1−(1−1/ep)k) 份。
    • TP + SP（Megatron）。每个块前向 AG + RS，反向 3 次 AG + 1 次 RS，MLA 的 AG 按压缩后的宽度。torchtitan 的 TP 按 Column AG + Row RS 前后向各一次算。
    • CP。Megatron：p2p 环（KV 绕 cp−1 步，可藏在注意力后面）、all-gather、a2a（Ulysses）；GDN 按头 a2a，KDA 可以按段传 FP32 状态。torchtitan：all-gather KV 或 Ulysses。
    • 步级。micro-batch 数 = 每 step token ÷ (DP × CP × 每卡 token)。PP 气泡 (p−1)/v 个 micro-batch。Megatron 分布式优化器：梯度 FP32 reduce-scatter + 参数 BF16 all-gather，可与反向 / 前向重叠；torchtitan FSDP2 每个 micro-batch 都要 all-gather 参数（reshard 时反向再一次）+ reduce-scatter 梯度。GPU Adam ≈ 30 B/参数 HBM 流量；CPU Adam 受 PCIe / C2C 和 CPU 吞吐限制。
    • 显存。Megatron：本地参数 BF16 + FP32 main_grad 6 B/参数，加上分片后的 12 B/参数 optimizer 状态（offload 时为 0）；torchtitan：分片后的 16 B/参数，加当前和预取块的全量参数。激活按每层保存的张量算，full 重算时每层只存输入。
    • MFU。这里按真实 FLOPs（含 KDA、MLA、indexer、CE）算；Megatron 自己报的 MFU 漏掉了 KDA 和 MLA 层，torchtitan 的注意力没按 causal 打折，两者都和这里不完全一致。

    训练并行展开的口径

    • 同一个核心。后训练的并行一节不另建模型：每张图、每个格子都是把“一个 step”的配置换几个参数，再调一次训练核心。框架是 Megatron 时，同样的 TP / CP / EP 度搬到 torchtitan 上（PP 去掉、分布式优化器换成 FSDP2）。推理取舍图同样只调推理核心的 decode 和 prefill。
    • CP。L = 本卡一份 K + V 的字节 = 2 B × S/C × 每 token KV 元素（DSA 加 indexer key）。每层 F+B 每卡发出：AllGather 3(C−1)L（full 重算 4(C−1)L），Ring (4C−2)L（重算 (5C−3)L），Ulysses 2 × 2(S/C)(Q + K′)d(C−1)/C（重算 ×1.5），K′ = max(Hkv, C)，MLA 的 latent 按 C 份复制。滑窗层只交换窗口大小的 halo。露出：Ulysses 全部露出；AllGather / Ring 第一块露出，其余能藏在 (C−1)/C 的注意力核心后面。连续切分时最忙 rank 的注意力核心 × (2 − 1/C)，首尾配对或 Ulysses 为 1。
    • EP 字节。按 expert 槽位 n·K(1−1/E)（NCCL all-to-all、Dist-MoE、MoK），按目的 rank 去重 n·(E−1)·p(E)，p(E) = 1 − C(Z−Z/E, K)/C(Z, K)（DeepEP），整份广播 (E−1)·n（AllGather + ReduceScatter）。MXFP8 dispatch 每元素 1 + 1/32 字节。full 重算时 NCCL 后端要重放 dispatch / combine。跨 NVLink 域的部分按 IB 带宽算。
    • EP 重叠。NCCL all-to-all 和 AllGather 串行，每层一次 host sync（全重算时两次）；DeepEP 串行，每次交换另加固定开销和一次 CPU 轮询；Dist-MoE 取 max(expert GEMM / 0.92, 线上时间) + barrier；MoK 让比例 f 的 SM 专做通信，取 max(GEMM / (1−f), 线上时间 / min(1, f/0.3))，再加 3% 握手开销。Dist-MoE 只在 SM100+ 的 NVLink 域内，MoK 只在 GB200 / GB300 NVL72 上。
    • FSDP。每层每卡线上字节 = Player·(F−1)/F·(a·2 + bg)，a = 2（reshard）或 1，bg = 4（FP32 梯度）或 2。dense 分片组 = dp_shard × cp / R，expert 分片组 = edp / R。FSDP 在后台流上，按链路（NVLink / IB）分别累加 CP、EP 和 FSDP 的线上时间，超出 micro-batch 计算时间的部分加上第一层的 gather 记为露出。HSDP 每步多一次梯度 all-reduce。all-gather / reduce-scatter 的可达带宽单独一个比例 ηag。
    • 推理取舍。每个配置把每个 DP rank 的并发从 1 扫到 min(显存上限, 引擎上限)，上下文按输入 + 输出/2。聚合部署每步顺带 prefill 完成掉的那些请求（一条 prompt 的 TTFT ÷ DP rank 数）；PD 分离把 prefill 卡按卡秒摊进分母。固定单用户速度时在 Pareto 曲线上线性插值。DeepInfer 的形状（prefill 小 EP、decode 宽 EP、attention 全 DP）按 SGLang 的 kernel 序列算。
    • 和实测对照。“和实测对照”一节把 8 × H200 上的 Qwen3.5 实测（attention 核心、整模型、expert FSDP、DeepEP 微基准）原样喂给训练核心，列出比值；MoK 只有和 DeepEP 的相对数字。

    量化核心的口径

    • 硬件。只算 Blackwell：B200 / B300（HGX）与 GB200 / GB300（NVL72）。dense 峰值 BF16 2.25 / FP8 4.5 / FP4 9（B300 13.5）PFLOPS，GB 系列 2.5 / 5 / 10（GB300 15），HBM 8 TB/s，和 LMSYS 引用的 HGX 规格一致。MMA 的峰值取两个操作数里精度高的那个：W4A8 按 FP8，W4A16 按 BF16。
    • 字节。每元素字节含块 scale：block FP8 权重 1 + 4/128²、激活 1 + 4/128；MXFP8 1 + 1/32；MXFP4 0.5 + 1/32；NVFP4 0.5 + 1/16，激活再加每 token 4 字节 FP32。
    • 激活量化。融合时没有额外开销（上一个算子直接写低精度）；单独一个 kernel 时多读一遍 BF16、写一遍量化值，至少一个 kernel 的最短时间。
    • W4A16。MMA 跑 BF16 峰值；每 BM 行的 CTA 在 CUDA core 上把整块权重反量化一遍，按可调的反量化吞吐记在算力一侧。
    • MoE。均匀路由下每个 expert 的行数 X ~ Poisson(T·k/E)；碰到的 expert 各读一遍权重；FLOPs 按补齐到 tile / 对齐后的行数算。auto 近似 FlashInfer TRTLLM MoE 的 tile 选择：next_pow2(λ)，夹在 8 到 64。
    • 训练三遍。fprop 用前向精度，dgrad / wgrad 用反向精度，wgrad 累加进 FP32 main_grad。量化 kernel：X 一次读、写行（和列）两份；W 是 1D 块时行列两份，2D 块一份，按 micro-batch 数摊；dY 行列两份（NVFP4 预训练在列方向做 16×16 RHT，记 32 FLOP/元素）；per-token scale 没融合时 GEMM 前后各多一次逐元素读写；dequantized 反向多一次反量化。
    • 放回整个模型。直接调用推理核心和训练核心，只换精度。推理核心里 expert 的 MMA 峰值取激活精度，激活单独量化时每层多一个 kernel；训练核心把精度用到所有 GEMM，NVFP4 + BF16 反向时加上未融合的 per-token 缩放。
    • 公开数据点。权重 = 时效（半衰期 12 个月）× 硬件匹配 × 来源类型，构建数据点库时算好。Hopper / AMD 的性能数字只作方向参考。
